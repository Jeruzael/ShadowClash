# M1.1 stabilization and acceptance verification

Date: 2026-10-29. Base: `9cfec37`. Scope: M1.1 only; M2 remains unstarted.

## Fixes

- Lobby cleanup resets HP, guard, progress bars, position/mode and rendered poses, round/wins/result, match ID/tick, invite/copy status, held inputs and the per-tab seat receipt. New matches snap to fresh positions without interpolating from the previous match. Late request acknowledgements cannot restore cleared membership.
- Leave/disconnect/expiry sends one final closure snapshot and immediately removes the room and all socket/seat/input resources. No later snapshots are sent for the terminated match. The shared simulation scheduler runs only while rooms exist, and `/health` reports its presence. Other live rooms keep running. Closed codes reject joins; remaining connected clients can start another room immediately.
- The header explicitly shows Connected to server, Waiting for opponent, Opponent connected (countdown), Match in progress, Opponent disconnected, or Connection lost. Refresh/loss clears the old seat and all lobby state; reconnecting the transport does not resume the match.
- Trusted-LAN opt-in uses `LAN_HOST=<host private IPv4>` and an exact interface binding. The Node server stays on loopback; the client proxies Socket.IO using its page origin. Exact LAN origins and custom ports are derived consistently. Wildcard/public/malformed binding addresses, invalid ports and malformed allowlist origins fail validation. HTTP invite-copy uses a manual selection fallback if the clipboard API is unavailable.

## Local multiplayer testing

Loopback: `npm ci` if needed, then `npm run dev`; open `http://127.0.0.1:5173` in two separate profiles/private windows. Fight a Friend → invite → Join room. A/D move, W jump, J punch, L block. Automated acceptance: `npx playwright install chromium` if needed, then `npm run test:e2e` (uses ports 5174/3002).

Second device on trusted Wi-Fi: find the host's Wi-Fi IPv4 with `ipconfig`; set `LAN_HOST` to that private address in root `.env`, keep `VITE_SERVER_URL` empty, run `npm run dev`, and use `http://<host-ip>:5173` on **both** devices. Only the client/proxy binds to that private interface. The exact LAN origin is allowed automatically; Node stays on `127.0.0.1:3001`. See the README's [LAN instructions and manual checklist](../README.md#two-devices-on-trusted-wi-fi), including firewall/private-network troubleshooting and restoring loopback defaults.

No LAN listener was enabled during this acceptance run. No firewall/network profile, router forwarding, tunnel, public hosting or unrelated system was changed. The observed Wi-Fi profile is Public, so any decision to permit trusted-network access remains a manual host setup step.

## Limits

Separate physical devices and public-internet play have **not** been verified. LAN configuration is prepared and tested as configuration, not claimed as a completed two-device session. IPv4 RFC1918 networks are supported for LAN opt-in. Input delay/latency fairness has not been assessed. Socket.IO detects ungraceful network failures through its transport/heartbeat behavior; physical outage timing was not measured. Refresh/disconnect deliberately ends an M1 match. M2 reconnect grace/seat resumption, full moves, timer/best-of-three, guard regeneration/break, rematch, AI, queue, final art and deployment remain out of scope.
