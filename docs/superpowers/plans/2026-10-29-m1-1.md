# M1.1 stabilization implementation plan

> Execute inline with systematic debugging, test-driven development, and one final independent code review.

**Goal:** Stabilize M1 room/lobby transitions and prepare trusted-LAN acceptance testing without M2.

**Spec:** The user's M1.1 request; existing `AGENTS.md`, `PRD.md`, and `docs/VERIFICATION.md` reviewed in full before editing.

**Architecture:** Preserve combat rules and the existing interface. Close a room with one final canonical notification and remove all membership/resources immediately. One server scheduler exists only while rooms exist. Reset every lobby HUD/visual value; distinguish transport and opponent/match states. Default services remain loopback. An explicit RFC1918 `LAN_HOST` binds only the client/proxy to that interface; Node remains on loopback.

## Constraints and review focus

- No M2 mechanics, seat resumption, assets, deployment, public binding or firewall changes.
- Closed room codes and input ownership cannot survive closure or refresh.
- Late snapshots/errors/acknowledgements must not restore a cleared room.
- Fresh lobby/waiting state resets HP/guard, progress bars, positions, pose, winner, score, tick, round, invite and seat receipt.
- Same-origin proxy and exact allowed origins must work on a second device; HTTP LAN clipboard fallback must not throw.
